Tối ưu truy vấn SQL Server: những case hay gặp

Tóm tắt: Kỹ thuật tối ưu truy vấn SQL Server thực tế: đọc execution plan, chọn index phù hợp, giải quyết parameter sniffing, và dùng công cụ monitoring để target bottleneck.

1. Đọc execution plan

Execution plan cho biết cách SQL Server thực thi query: index seek vs table scan, hash join vs nested loop. Nếu có table scan trên bảng lớn, cần xem xét index hoặc rewrite query.

2. Indexing strategies

Sử dụng clustered index cho ordering chính, non-clustered index cho cột hay dùng trong WHERE/JOIN/ORDER BY. Xem xét covering index (include columns) để tránh lookup. Dùng filtered index cho subset phổ biến để giảm kích thước index.

3. Parameter sniffing & statistics

Parameter sniffing có thể khiến plan không tối ưu cho mọi giá trị. Khắc phục bằng OPTIMIZE FOR UNKNOWN, plan guides, hoặc recompile tùy trường hợp. Đảm bảo statistics luôn cập nhật; auto update stats hoặc schedule update manual cho table lớn.

4. Avoid anti-patterns

Tránh SELECT *; tránh functions on predicates (e.g., WHERE YEAR(date) = 2024) vì phá index seek. Sử dụng proper joins và minimize subqueries khi có thể chuyển thành joins/CTE tối ưu.

5. Monitoring & tooling

Dùng Query Store để xem plan changes, SQL Profiler/Extended Events để bắt slow queries. Sử dụng DMV (sys.dm_exec_query_stats) để tìm top expensive queries và bắt đầu tối ưu từ đó.

6. Example

-- Add covering index
CREATE NONCLUSTERED INDEX IX_Order_CustomerDate
ON dbo.Orders(CustomerId, OrderDate)
INCLUDE (TotalAmount);

Kết luận

Performance tuning là lặp: measure → diagnose → change → measure lại. Tập trung vào queries chiếm resource nhiều nhất và sử dụng tools để giám sát lâu dài.
