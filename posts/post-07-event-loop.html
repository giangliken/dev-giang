Tìm hiểu về Event Loop

Bí mật đằng sau khả năng xử lý bất đồng bộ của JavaScript.

JavaScript thường được mô tả là "đơn luồng" (single-threaded), nhưng làm thế nào nó có thể xử lý các tác vụ như setTimeout, gọi API, hay DOM events mà không bị "đứng"? Câu trả lời nằm ở Event Loop.

Các thành phần chính

Mô hình đồng thời của JavaScript bao gồm ba phần chính:

  • Call Stack: Nơi các lệnh thực thi được xếp vào. "Last in, First out" (LIFO). Khi một hàm được gọi, nó được đẩy vào stack. Khi hàm trả về, nó được đưa ra khỏi stack.
  • Web APIs: Cung cấp bởi môi trường (ví dụ: trình duyệt), nơi các tác vụ bất đồng bộ như setTimeout hay fetch được xử lý. Chúng không nằm trong Engine JavaScript.
  • Callback Queue (hoặc Task Queue): Nơi các hàm callback được xếp hàng chờ để được đẩy vào Call Stack sau khi tác vụ bất đồng bộ tương ứng đã hoàn thành.

Event Loop hoạt động như thế nào?

Event Loop là một vòng lặp vô tận có nhiệm vụ rất đơn giản: Nó liên tục kiểm tra xem Call Stack có trống không. Nếu Call Stack trống, nó sẽ lấy tác vụ đầu tiên từ Callback Queue và đẩy vào Call Stack để thực thi.

Hãy xem ví dụ sau:

console.log('Bắt đầu'); // 1

setTimeout(() => {
  console.log('Bên trong setTimeout'); // 3
}, 0);

console.log('Kết thúc'); // 2

Luồng thực thi sẽ diễn ra như sau:

  1. console.log('Bắt đầu') được đẩy vào Call Stack và thực thi ngay lập tức. Output: "Bắt đầu".
  2. setTimeout được đẩy vào Call Stack. Engine JavaScript thấy đây là một Web API, nên nó chuyển hàm callback vào Web APIs để xử lý timer (dù là 0ms) và sau đó đưa setTimeout ra khỏi Call Stack.
  3. console.log('Kết thúc') được đẩy vào Call Stack và thực thi. Output: "Kết thúc".
  4. Sau khoảng 0ms, timer của Web API kết thúc. Hàm callback () => { console.log(...) } được chuyển vào Callback Queue.
  5. Event Loop thấy Call Stack đã trống. Nó bốc callback từ Queue, đẩy vào Call Stack.
  6. Hàm callback được thực thi. console.log('Bên trong setTimeout') được gọi. Output: "Bên trong setTimeout".

Đây là lý do tại sao setTimeout với delay 0ms vẫn chạy sau cùng. Nó giải thích cách JavaScript có thể xử lý các tác vụ I/O mà không làm ứng dụng của bạn bị treo.
