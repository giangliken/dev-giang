CI/CD cơ bản cho .NET & Flutter

Tóm tắt: Hướng dẫn thiết lập CI/CD thực tế cho .NET backend & Flutter app: cấu trúc pipeline, caching, test stages, release strategy và best practices cho secrets/rollbacks.

1. Pipeline stages

Phân tách pipeline: install deps → build → test → package/artifact → deploy. Đảm bảo mỗi stage fail fast nếu tồn tại lỗi.

2. Caching

Cache NuGet packages, .pub-cache (Flutter), node_modules nếu có frontend. Cache giúp giảm thời gian build và tiết kiệm CI minutes.

3. Testing & quality gates

Chạy unit tests, static analysis (linters), và integration tests. Thiết lập quality gates: không merge nếu coverage giảm hoặc test fail. Sử dụng matrix build nếu cần kiểm tra nhiều version.

4. Artifact & deployment strategy

Publish build artifacts (zip, docker image, apk). Sử dụng staging environment cho smoke tests và canary hoặc blue-green deployment để giảm rủi ro khi release production.

5. Secrets & configuration

Quản lý secrets qua CI provider (GitHub Secrets, Azure Key Vault). Không commit secrets vào repo. Dùng environment-specific configuration và feature flags để điều khiển behavior production.

6. Rollback & monitoring

Luôn có kế hoạch rollback (revert release hoặc deploy previous artifact). Instrument application với metrics và alerts để detect regressions sớm.

7. Example (GitHub Actions snippet)

name: CI
on: [push]
jobs:
    build:
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v3
            - name: Setup .NET
                uses: actions/setup-dotnet@v3
            - name: Restore & Build
                run: dotnet build --no-restore
