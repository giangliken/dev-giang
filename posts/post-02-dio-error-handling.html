Dio, error handling & cách mình show lỗi cho user

Tóm tắt: Hướng dẫn cấu hình Dio cho ứng dụng Flutter production: interceptors, token refresh, retry/backoff, phân loại lỗi và cách map lỗi sang UX phù hợp, kèm ví dụ thực tế và khuyến cáo test/observability.

Thiết lập cơ bản và interceptors

Khởi tạo Dio với BaseOptions (baseUrl, connectTimeout, receiveTimeout). Thêm interceptor để attach token, handle logging và map lỗi. Interceptor là nơi tập trung xử lý cross-cutting concerns như authorization và request/response tracing.

Token refresh pattern

Khi nhận 401, interceptor nên pause các request hiện tại, thực hiện refresh token một lần và sau đó replay các request đã bị pause. Tránh race condition bằng cách queue các request trong khi refresh đang thực hiện. Nếu refresh lỗi, force logout và dẫn người dùng đến màn hình đăng nhập.

Retry & exponential backoff

Chỉ retry cho lỗi tạm thời: network error, timeouts, 5xx. Sử dụng exponential backoff với jitter và giới hạn số lần retry. Tránh retry cho 4xx (validation/auth errors) vì không có lợi và có thể gây duplicate side-effects.

Map lỗi thành UX

Phân loại lỗi rõ ràng: validation (show field errors), auth (redirect/login prompt), network (offline banner hoặc retry UI), server (friendly message + report). Luôn giữ message ngắn gọn cho user và log đầy đủ cho dev.

Observability & Debugging

Ghi log request/response ở mức phù hợp (avoid sensitive data). Sử dụng Sentry hoặc hệ thống tương tự để capture exceptions. Thêm correlationId vào headers để liên kết client log với server traces.

Ví dụ pattern (pseudo)

final dio = Dio(BaseOptions(baseUrl: apiBase, connectTimeout: 5000));
dio.interceptors.add(InterceptorsWrapper(
  onRequest: (r, h) => attachAuthHeader(r),
  onError: (e, h) => handleAuthRefreshOrRetry(e, h),
));

Testing

Viết unit test cho interceptor logic (mock HTTP layer). Kiểm tra token refresh, retry rules và mapping lỗi sang UI. Thử nghiệm trên mạng mô phỏng (throttling, packet loss) để đảm bảo UX chấp nhận được.

Kết luận

Thiết kế lỗi và retry từ đầu giúp ứng dụng ổn định trong môi trường mạng không ổn định. Sử dụng interceptors để tập trung xử lý, map lỗi hợp lý cho UX và instrument logging/tracing cho debugging hiệu quả.
