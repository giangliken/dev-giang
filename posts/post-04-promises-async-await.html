Bất đồng bộ: Promises và Async/Await

Từ callback hell đến cú pháp thanh lịch với Promises và async/await.

JavaScript là ngôn ngữ đơn luồng (single-threaded), nhưng nó có thể thực hiện các tác vụ bất đồng bộ như gọi API, đọc file mà không chặn luồng chính, nhờ vào Event Loop, Promises và async/await.

1. Từ Callback Hell đến Promises

Trước đây, các hàm bất đồng bộ thường dùng callback. Khi nhiều tác vụ lồng nhau, chúng ta rơi vào "callback hell", khiến code rất khó đọc.

// Callback hell
getData(a, (resultA) => {
  getMoreData(resultA, (resultB) => {
    getEvenMoreData(resultB, (resultC) => {
      console.log(resultC);
    });
  });
});

Promise ra đời để giải quyết vấn đề này. Một Promise đại diện cho kết quả (thành công hoặc thất bại) của một tác vụ bất đồng bộ.

const myPromise = new Promise((resolve, reject) => {
  const success = true; // Giả lập tác vụ thành công
  if (success) {
    resolve('Dữ liệu đã sẵn sàng!');
  } else {
    reject('Đã có lỗi xảy ra.');
  }
});

myPromise
  .then(data => console.log(data)) // 'Dữ liệu đã sẵn sàng!'
  .catch(error => console.error(error));

2. Async/Await: Cú pháp cho Promises

ES2017 (ES8) giới thiệu async/await, một cú pháp "syntactic sugar" giúp làm việc với Promises dễ dàng hơn, cho phép viết code bất đồng bộ trông giống như code đồng bộ.

  • async: Đặt trước một hàm để cho biết nó sẽ luôn trả về một Promise.
  • await: Chỉ có thể dùng bên trong một hàm async. Nó sẽ tạm dừng việc thực thi hàm cho đến khi Promise được giải quyết (resolved) hoặc bị từ chối (rejected).
async function fetchData() {
  try {
    const response = await fetch('https://api.example.com/data');
    if (!response.ok) {
      throw new Error('Network response was not ok');
    }
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('Lỗi khi fetch data:', error);
  }
}

fetchData();

Với async/await, luồng code trở nên rõ ràng và dễ theo dõi hơn rất nhiều, đặc biệt khi xử lý nhiều tác vụ bất đồng bộ liên tiếp.
