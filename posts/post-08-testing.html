Unit & Integration test cho dự án học thuật

Tóm tắt: Chiến lược testing: unit, integration, e2e; cách thiết kế test maintainable cho dự án học thuật và production-ready systems.

1. Test pyramid

Ưu tiên unit tests (nhanh, nhiều) → integration tests (tích hợp thành phần) → e2e (chậm, ít). Giữ balance để có feedback nhanh và coverage end-to-end.

2. Unit tests

Mock dependency để test business logic thuần túy. Dùng frameworks: xUnit/NUnit cho .NET, Mockito cho Dart/Flutter. Viết test deterministic, independent và small.

3. Integration tests

Sử dụng in-memory DB (SQLite) hoặc Testcontainers để dựng DB thực tế. Integration tests phát hiện lỗi config, mapping và giao tiếp giữa module.

4. Fixtures & seed data

Tạo fixtures nhỏ gọn, deterministic. Evict/cleanup state between tests to avoid flakiness. Use factories to generate test data consistently.

5. CI integration

Chạy tests trong pipeline và fail build khi test không pass. Chạy unit tests en masse, integration tests selectively (e.g., nightly) nếu quá nặng.

6. Maintainability

Keep tests readable and focused; avoid testing implementation details. Refactor tests alongside production code to avoid brittle suites.
